# Каскад — спецификация визуальных концепций A и B для главной страницы

Версия: 1.0  
Дата: 15 сентября 2026  
Назначение: передача в чат «Разработка макета» для реализации двух переключаемых визуальных концепций на общей HTML-структуре.

---

## 1. Статус документа и источники истины

### 1.1. Приоритет источников

1. **Согласованный варфрейм-прототип главной страницы** — источник истины для состава, порядка и содержания блоков.
2. **Последние полные макеты Concept A и Concept B** — источник истины для визуального направления, типографики, цветовых поверхностей и общей композиции.
3. **Последние отдельные итерации блоков** — имеют приоритет над соответствующими блоками в более ранних полных макетах.
4. Существующая адаптивная и техническая основа проекта — источник истины для контейнеров, контрольных ширин и уже реализованного поведения, если это не противоречит документу.

### 1.2. Актуальные визуальные референсы

- Полная концепция A: фрейм/экран `A-Design(1)`.
- Полная концепция B: фрейм/экран `B-Design(1)`.
- Производственный блок A: последняя светлая версия внутри `A-Design(1)`.
- Производственный блок B: последняя матричная версия с большой фотографией слева, горизонтальным модулем сверху справа и двумя модулями снизу справа. Эта версия заменяет ряд из четырёх одинаковых карточек в `B-Design(1)`.

### 1.3. Правило разрешения противоречий

- Структурный конфликт: сохранять варфрейм.
- Визуальный конфликт: использовать последнюю точечную итерацию.
- Неясная деталь: выбрать решение, совместимое с общей DOM-структурой и переключением концепций через CSS.
- Не добавлять новые смысловые блоки, поля формы, факты, вкладки и пользовательские сценарии без отдельного согласования.

---

## 2. Цель реализации

Нужно реализовать **одну главную страницу с одним семантическим DOM**, поддерживающую две визуальные концепции:

- **Concept A — «Завод-Гарант»**: эмоциональная производственная подача, крупная фотография, выразительный Bebas Neue, сильный графитовый контраст, красный как коммерческий сигнал.
- **Concept B — «Инженерная система»**: светлая техническая подача, IBM Plex Sans и IBM Plex Mono, индексы секций, тонкие линии, модульная сетка, красный как функциональный маркер.

Переключение должно менять стили, раскладку элементов и тематические декоративные изображения, но не должно создавать две отдельные страницы или дублировать смысловой контент.

## 3. Обязательные архитектурные правила

### 3.1. Одна DOM-структура

Запрещено:

- создавать отдельную разметку страницы для A и B;
- дублировать блоки и переключать их через `display: none`;
- иметь разные наборы полей формы;
- иметь разные тексты, названия и порядок смысловых элементов;
- использовать настоящую HTML-таблицу только в B, если в A тот же контент является списком.

Разрешено:

- менять CSS Grid/Flex-раскладку;
- менять `grid-area`, `grid-column`, порядок и размеры на desktop;
- накладывать текст на изображение в A и располагать его статически в B;
- менять фоновые и декоративные изображения через CSS;
- добавлять декоративные линии, индексы и графические маркеры псевдоэлементами;
- менять типографику, цвета, границы, радиусы и пропорции.

### 3.2. Переключатель концепций

Рекомендуемый корневой атрибут:

```html
<body data-concept="a">
```

Допустимые значения: `a`, `b`.

Принцип CSS:

```css
[data-concept="a"] .section { /* стили A */ }
[data-concept="b"] .section { /* стили B */ }
```

Для презентации должны поддерживаться прямые URL, например:

- `/?concept=a`
- `/?concept=b`

Переключатель может сохранять выбор в `sessionStorage` или эквивалентном механизме. Query-параметр имеет приоритет над сохранённым выбором.

### 3.3. Изображения, различающиеся между темами

Тематические hero-изображения разрешено переключать одним из способов:

1. CSS custom property с `background-image` в общем контейнере `.hero__media`;
2. две декоративные media-плоскости внутри одного общего контейнера, переключаемые стилями и исключённые из accessibility tree;
3. синхронное обновление `src` при смене `data-concept`, если изображение должно оставаться семантическим `<img>`.

Не дублировать текстовый контент hero.

### 3.4. Семантический порядок

DOM должен оставаться логичным без CSS:

1. индекс/метка секции;
2. заголовок;
3. вводный текст;
4. список элементов;
5. управляющие элементы.

На мобильном контент отображается преимущественно в этом же порядке.

## 4. Порядок блоков главной страницы

Порядок фиксирован согласованным варфреймом:

1. Header.
2. Hero.
3. `01` Основная продукция завода.
4. `02` Готовые решения и монтаж под ключ.
5. `03` Специальные сервисы и программы сотрудничества.
6. `04` Выполненные объекты.
7. `05` Производственный комплекс и технологии завода «Каскад».

Полные дизайн-фреймы могут временно не содержать секции 03, 04 и Footer, но в реализации они обязательны и должны занимать позиции варфрейма.

## 5. Общие дизайн-токены

### 5.1. Базовая палитра

| Токен | Рабочее значение | Назначение |
|---|---:|---|
| Graphite | `#111617` | тёмные поверхности, основной контраст |
| White | `#FFFFFF` | основной светлый фон |
| Surface light | `#F3F4F4` | светлые секции и технические поверхности |
| Surface mid | `#E5E7E7` | текстовые плоскости модулей B |
| Border | `#D8DCDC` | тонкие границы и разделители |
| Text primary | `#111617` | основной текст на светлом фоне |
| Text secondary | `#5F6768` | метаданные и вторичный текст |
| Red | `#E32E35` | фирменный акцент и активное действие |

Перед реализацией проверить фактические переменные проекта и не создавать дублирующие токены при наличии эквивалентных.

### 5.2. Геометрия

- Использовать существующий контейнер и адаптивную сетку проекта.
- Desktop: 12-колоночная логика.
- Основные секции выравниваются по одним и тем же левому и правому краям.
- Тени не использовать.
- A: радиус 0–2 px, допускается 0 на крупных плоскостях.
- B: радиус 0–4 px; для технических матриц предпочтительно 0–2 px.
- Граница: обычно 1 px.

### 5.3. Вертикальный ритм

Рабочие диапазоны, с учётом существующей адаптивной основы:

| Контекст | Отступ секции сверху/снизу |
|---|---:|
| Desktop ≥1080 | 88–112 px |
| Tablet 768–1079 | 72–88 px |
| Mobile ≤767 | 56–72 px |

Секции не должны искусственно растягиваться до экрана. Приоритет — ритм полного лендинга и отсутствие избыточной высоты.

## 6. Типографика

### 6.1. Concept A

- Display-заголовки и крупные числовые показатели: **Bebas Neue**.
- Основной текст, UI, формы и технические обозначения: **Golos Text**.
- Заголовки Bebas преимущественно прописными.
- Интерфейсные подписи не набирать Bebas, если страдает читаемость.
- Символы `№` и `₽` не использовать в Bebas: соответствующие строки набирать Golos Text или выделять эти символы отдельным span с Golos.

Характер:

- компактный межстрочный интервал display-заголовков;
- крупные заголовки с жёсткими переносами;
- высокая контрастность заголовок/текст;
- красным выделять фразу или ключевое значение, а не произвольные отдельные буквы.

### 6.2. Concept B

- Заголовки, основной текст и UI: **IBM Plex Sans**.
- Индексы, технические подписи, служебные метки: **IBM Plex Mono**.
- Заголовки преимущественно в обычном регистре, без обязательного uppercase.
- Mono не использовать для длинных абзацев.

Характер:

- ясная иерархия размеров;
- тонкие горизонтальные линии;
- индексы формата `01 / ПРОДУКЦИЯ`;
- числовые значения допускается выделять Mono или усиленным Sans.

### 6.3. Минимальные требования к тексту

- Основной desktop-текст: ориентир 16–18 px.
- Mobile: не менее 15–16 px для основного текста.
- Подписи: не менее 12 px, если они несут смысл.
- Line-height основного текста: 140–155%.
- Контраст обычного текста: не ниже WCAG AA 4.5:1.

## 7. Header

### 7.1. Общая структура

- Логотип.
- Основная навигация.
- Контакты: телефон и email.
- Основная кнопка «Заказать расчёт».
- На mobile: логотип и кнопка меню; навигация открывается в общем drawer-компоненте.

### 7.2. Concept A

- Белая поверхность.
- Логотип слева.
- Навигация компактная, без фоновых плиток.
- Пункт «Продукция» сопровождается небольшим красным знаком/сеткой.
- Контакты справа, CTA — контурная кнопка.
- Активные и hover-состояния: красная линия/текст, без залитых табов.

### 7.3. Concept B

- Та же разметка и контент.
- Допускаются тонкие вертикальные разделители между функциональными зонами header.
- Техническая точность выравнивания важнее декоративных акцентов.
- Красный используется в маркере «Продукция» и активном состоянии.

### 7.4. Адаптивность

- До существующего breakpoint desktop-navigation использовать полную навигацию.
- Ниже breakpoint — логотип + hamburger.
- Минимальная зона нажатия: 44×44 px.
- Контактные данные перемещаются в drawer, а не исчезают полностью.

## 8. Hero

### 8.1. Общая структура

- optional overline/метка;
- один H1;
- описание из двух смысловых строк/предложений;
- основной CTA;
- общий `.hero__media` для тематического изображения.

### 8.2. Concept A

- Полноширинная производственная фотография.
- Поверх фото — графитово-синий/нейтральный тёмный overlay, обеспечивающий читаемость.
- Контент расположен слева внутри общего контейнера.
- H1 — Bebas Neue, uppercase, белый, крупный, 3 строки на desktop.
- Основной CTA — красная залитая кнопка.
- Допустим тонкий геометрический знак/chevron справа как декоративный элемент.
- Не использовать сплошную красную заливку hero.

Рабочая высота desktop: ориентир 520–600 px с учётом существующего header.

### 8.3. Concept B

- Светлый фон `Surface light` с очень деликатной диагональной графикой.
- Слева: overline `С 2007 ГОДА`, H1, описание и чёрный CTA.
- Справа: крупный изолированный фрагмент 3D-панели/сетки с режимом `contain` или контролируемым кропом.
- Изображение не смешивается с фоном как атмосферная фотография: оно воспринимается как объект изучения.
- Красный в hero используется минимально.

Рабочая высота desktop: ориентир 500–560 px.

### 8.4. Mobile

- A: фотография остаётся фоном; overlay усиливается; H1 сокращает размер, но сохраняет Bebas и жёсткие переносы; CTA на всю доступную ширину.
- B: текст идёт первым; объект может размещаться на фоне справа/снизу и не должен ухудшать чтение; CTA на всю ширину.
- Не допускать горизонтального overflow из-за крупного H1 или hero-media.

## 9. Блок 01 — Основная продукция завода

### 9.1. Общая структура

- Метка секции — присутствует в DOM; в A может быть визуально скрыта как декоративная, но остаётся доступной для общей структуры.
- Заголовок.
- Ссылка «Смотреть весь каталог».
- Список из четырёх продуктов.
- В каждом продукте: изображение, заголовок, описание, ссылка.

### 9.2. Concept A

- Заголовок Bebas, uppercase.
- Без технической линии над заголовком.
- Четыре равных элемента на desktop.
- Изображение продукта на нейтральном светлом фоне.
- Текстовая поверхность светло-серая, без заметной рамки.
- Заголовок и ссылки — Golos Text, полужирные.
- Ссылка каталога справа — контурная кнопка.

### 9.3. Concept B

- Индекс `01 / ПРОДУКЦИЯ` в IBM Plex Mono.
- Тонкая линия на ширину секции.
- Заголовок IBM Plex Sans.
- Четыре карточки с тонкой границей или на белой поверхности.
- Изображения и текст разделены спокойной геометрией.
- Ссылка на каталог выглядит как текстовое действие, а не отдельная крупная кнопка.

### 9.4. Адаптивность

- Desktop ≥1080: четыре колонки.
- Tablet: две колонки либо горизонтальный scroll — использовать уже закреплённое в проекте поведение.
- Mobile: горизонтальный список с 1.10–1.20 карточки в viewport, `scroll-snap`, без обязательной стрелочной навигации.
- Карточки внутри одного списка имеют согласованную высоту текстовой части.

## 10. Блок 02 — Готовые решения и монтаж под ключ

### 10.1. Общая структура

- Метка секции.
- Заголовок.
- Три решения.
- В каждом: изображение, заголовок, описание, ссылка.

### 10.2. Concept A

- Заголовок Bebas, uppercase.
- Три равные editorial-колонки.
- Большая цветная фотография сверху.
- Под фотографией — заголовок Bebas, описание Golos и текстовая ссылка.
- Без общей карточной подложки и без рамки.
- Блок должен ощущаться как витрина реальных применений, а не каталог товаров.

### 10.3. Concept B

- Индекс `02 / ТИПОВЫЕ РЕШЕНИЯ` и линия.
- Три горизонтальных ряда друг под другом.
- Изображение слева, текст справа на светлой поверхности.
- Одинаковая высота рядов.
- Заголовок IBM Plex Sans, метаданные и служебные элементы могут использовать Mono.
- Радиус минимальный; тени отсутствуют.

### 10.4. Адаптивность

- A на mobile: один элемент в строке либо горизонтальная лента; предпочтение выбрать по общей длине страницы после интеграции секций 03–06.
- B на mobile: каждый горизонтальный ряд превращается в вертикальный модуль «изображение → текст».
- Не скрывать описания и ссылки.

## 11. Блок 03 — Специальные сервисы и программы сотрудничества

Блок не отрисован детально в финальных фреймах. Реализовать строго по варфрейму: заголовок и четыре ссылки, без добавления новых описаний.

### 11.1. Общая структура

- Заголовок.
- Список из четырёх ссылок:
  - проектировщикам и архитекторам;
  - дилерам и монтажным организациям;
  - юридическим лицам и застройщикам;
  - частным клиентам.
- Каждый элемент: опциональный индекс, текст ссылки, стрелка.

### 11.2. Concept A

- Компактная непрерывная навигационная лента, не четыре самостоятельные карточки.
- Фон ленты: `Surface light` или Graphite в зависимости от соседнего блока после общей сборки.
- Четыре равных сегмента, разделённых тонкими вертикальными линиями.
- Текст Golos, полужирный; допускается короткий Bebas-маркер.
- Стрелка выравнивается по правому краю сегмента.
- Hover: красная нижняя линия или красная стрелка; не заливать весь сегмент красным.

### 11.3. Concept B

- Индекс секции `03 / СЕРВИСЫ` и верхняя линия.
- Та же четверка ссылок оформлена как технический навигационный регистр.
- Каждый сегмент получает индекс `01–04` в Mono.
- Общая рамка или единая линия сетки; отдельные тени и плавающие карточки отсутствуют.
- Hover/focus: красный индекс и сдвиг стрелки на 2–4 px.

### 11.4. Адаптивность

- Desktop: четыре сегмента в один ряд.
- Tablet: сетка 2×2.
- Mobile: четыре строки; каждая строка сохраняет стрелку и достаточную зону нажатия ≥44 px.

## 12. Блок 04 — Выполненные объекты

Блок не отрисован детально в финальных фреймах. Использовать структуру и контент варфрейма.

### 12.1. Общая структура

- Заголовок.
- Ссылка «Смотреть все объекты».
- Carousel/track с проектами.
- На desktop одновременно видны два проекта.
- В каждом проекте: изображение, категория/тег, название, краткие параметры, ссылка.
- Управление: назад, счётчик, вперёд.

### 12.2. Concept A

- Заголовок Bebas, uppercase.
- Две крупные photo-led плитки.
- Категория отображается небольшой графитовой плашкой поверх изображения.
- Изображение занимает основную часть проекта.
- Название Bebas или усиленный Golos — выбрать по фактической длине; основной текст Golos.
- На изображении допустим лёгкий нижний gradient, но основной текст проекта предпочтительно оставить под фотографией.
- Стрелки — простые квадратные/контурные элементы, активное состояние красное.

### 12.3. Concept B

- Индекс `04 / ОБЪЕКТЫ` и линия.
- Два проекта являются элементами единого технического track.
- Изображения имеют одинаковую высоту и строгий кроп.
- Подпись проекта собрана как спецификация: Mono-категория, Sans-название, строка параметров.
- Тонкая граница; отсутствие теней.
- Счётчик вида `01 / 03` — IBM Plex Mono.
- Красный применяется для активной стрелки или текущего номера, а не как крупная заливка.

### 12.5. Адаптивность

## 16. Общие интерактивные состояния

### 16.4. Motion

- Без параллакса и тяжёлых scroll-анимаций на этапе концептуального прототипа.
