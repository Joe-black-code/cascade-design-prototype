# Интерактивный прототип сайта «Каскад»

Статический многостраничный прототип на Vite, обычном HTML, CSS и vanilla JavaScript. Сквозные HTML-компоненты подключаются из `src/partials` во время сборки с помощью Handlebars; браузер получает готовые статические страницы без runtime `fetch()`.

## Требования

- рекомендуемая локальная версия — Node.js 22 через `.nvmrc`;
- минимальная поддерживаемая версия — Node.js 22.12; более новые совместимые версии разрешены;
- npm и `package-lock.json` используются как основной механизм установки зависимостей.

## Установка

Для воспроизводимой установки зафиксированных зависимостей:

```sh
npm ci
```

## Локальная разработка

```sh
npm run dev
```

Vite выведет адрес локального сервера. Исходные страницы находятся в `src/pages`.

## Сборка и проверка

```sh
npm run build
npm run verify
```

`npm run build` очищает и заново создаёт `dist`. Команда `npm run verify` сначала собирает проект, затем проверяет страницы, структуру, обязательный контент, responsive-контракт, локальные ресурсы и пригодность относительных путей для статического хостинга.

## Браузерные E2E-тесты

```sh
npx playwright install chromium
npm run test:e2e
```

`npm run test:e2e` сначала создаёт production-сборку `dist`, затем запускает официальный Playwright Test только в Chromium через Vite Preview на `http://127.0.0.1:4173`. Сценарии из `tests/e2e` выполняются в desktop viewport 1440×1000 и mobile viewport 390×844. Trace и screenshot сохраняются только при ошибке. Локальный HTML-отчёт открывается командой `npm run test:e2e:report`. Статическая команда `npm run verify` не требует браузера.

Для сокращённой responsive-регрессии после уже выполненного `npm run verify` используется команда:

```sh
npm run test:e2e:responsive
```

Она не повторяет production-сборку и запускает только responsive foundation/layout и последовательную проверку основных и граничных ширин CP-1.3C. Полный `npm run test:e2e` требуется при изменении общей интерактивной архитектуры, существенном изменении DOM, завершении крупной функциональной контрольной точки и перед публикацией стенда; изменение отдельного компонента проверяется его spec. Responsive-параметры остаются предварительными до подключения реальной типографики и изображений.

## Публикация

На статический хостинг нужно загрузить **содержимое** каталога `dist`:

- `index.html`;
- `catalog.html`;
- каталог `assets` с общими CSS, JavaScript и SVG-ресурсами.

Сборка использует относительную базу и относительные переходы между страницами, поэтому содержимое `dist` допускается размещать как в корне домена, так и в произвольной вложенной директории.

## Структура

- `src/pages` — две входные HTML-страницы;
- `src/partials` — подключаемые на этапе сборки компоненты: сквозные элементы лежат в корне, секции страниц — в `home` и `catalog`, общая форма расчёта — в `forms`;
- `src/styles/base.css` — единая CSS-точка входа, reset, доступность и технические состояния; она подключает базовые токены из `tokens.css` и нейтральные layout-примитивы из `layout.css`;
- `src/scripts` — единая точка входа vanilla JavaScript, независимые компоненты модального окна, форм расчёта, десктопного мегаменю, мобильной drill-down-навигации, слайдера объектов и общего уведомления о недоступных разделах, а также utility блокировки прокрутки;
- `src/assets` — шрифты, иконки и изображения сборки;
- `tests/e2e` — браузерные спецификации Playwright; `tests/fixtures` — локальные тестовые файлы;
- `playwright.config.js` — Chromium-проекты, viewport, `webServer` и политика артефактов;
- `scripts/verify-build.mjs` — автоматическая техническая проверка результата сборки;
- `docs/source` — предоставленные текстовые исходные материалы;
- `reference/source-archives` и `reference/brand` — исходный архив и логотип;
- `reference/prototype-original` — неизменённые файлы исходного HTML-прототипа;
- `reference/SHA256SUMS` — контрольные суммы исходных reference-материалов;
- `dist` — результат сборки (не хранится в Git).

## Responsive-фундамент CP-1.3A

- `src/styles/tokens.css` хранит только исходные брендовые цвета, компактную шкалу расстояний и предварительные глобальные параметры layout;
- `src/styles/layout.css` содержит канонический fluid-контейнер `.layout-container` и opt-in сетку `.layout-grid`; существующие секции и карточки к сетке автоматически не подключаются;
- контейнер занимает доступную ширину за вычетом fluid-полей `1–2rem`, центрируется и ограничен шириной `85.5rem` (`1368px`); внешние `header`, `main` и `footer` остаются полноширинными, контейнер ограничивает только внутреннюю строку хедера и содержимое футера, а внутренние контейнеры секций будут добавляться на этапе CP-1.3B;
- число условных колонок меняется с 4 на 8 при `48rem` (`768px`) и с 8 на 12 при `67.5rem` (`1080px`); реальные точки перестроения компонентов будут уточнены во время визуальной работы;
- статический контракт проверяется командой `npm run verify`, а контрольные ширины 360, 390, 768, 1024, 1440 и 1920 px — командой `npm run test:e2e`.

CP-1.1, CP-1.2 и весь CP-1.3 завершены. Визуальная система намеренно не реализована.

## Адаптивная компоновка CP-1.3B

`src/styles/responsive.css`, подключённый после `tokens.css` и `layout.css`, содержит только нейтральные правила композиции и responsive visibility. Страничные области используют схему `section` (полноширинная оболочка) → `.layout-container` (единственный внутренний контейнер); `main`, header/footer и overlay остаются полноширинными.

Предварительный breakpoint навигации — `67.5rem` (1080 px): ниже доступны mobile toggle и полноэкранная drill-down-навигация, от breakpoint — desktop navigation, контакты, CTA и четыре полноширинных мегаменю. При пересечении breakpoint открытая несовместимая навигация закрывается автоматически.

Предварительные схемы compact/medium/wide: продукция — 2/2/4 колонки, решения — 1/2/3, партнёрские программы — 1/2/4, проекты — 1/2/2, факты производства — 1/2/4. Каталог использует 2 колонки до 1080 px, 3 от 1080 px и 4 от 1440 px. Эти решения подлежат проверке после появления типографики и визуального слоя.

Полный набор browser tests запускается командой:

```sh
npm run test:e2e
```

## Фундамент концепций CP-2.1A

Обе страницы используют единый DOM и выбирают визуальную систему query-параметром: `?concept=a` для A «Завод-Гарант» и `?concept=b` для B «Инженерная система». Без параметра и при невалидном значении применяется A; текущий URL при этом не переписывается. Vanilla JS-модуль переносит допустимый `concept` только в относительные переходы между `index.html` и `catalog.html`, не используя storage и не меняя внешние, `tel:`, `mailto:` или hash-ссылки.

`src/styles/base.css` остаётся единственной точкой входа и последовательно подключает `fonts.css`, общие `tokens.css`, `themes/concept-a.css` и `themes/concept-b.css`, затем `layout.css` и `responsive.css`. Fontsource локально поставляет Bebas Neue 400; Golos Text 400/500/600; IBM Plex Sans 400/500/600/700; IBM Plex Mono 400. Runtime-запросов шрифтов к CDN нет.

Основной `.layout-container` ограничен `85.5rem` (1368 px). `.layout-container--wide` для `header-inner` ограничен `112.5rem` (1800 px), а его gutter — максимум `2.5rem` (40 px). Глобальная сетка переключается 4 → 8 → 12 колонок на 768 и 1080 px. Независимый предварительный breakpoint навигации — `80rem` (1280 px): до 1279 px используется mobile navigation, от 1280 px — desktop navigation.

Целевые проверки после `npm run verify` не выполняют повторную сборку:

```sh
npm run test:e2e:concept
npm run test:e2e:responsive
```
