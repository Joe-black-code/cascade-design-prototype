# Правила проекта «Каскад»

- Перед началом работы читать `Cascade-Design-Roadmap.md`.
- Не изменять файлы в `reference/prototype-original`.
- Сквозные элементы страниц хранить в build-time partial-компонентах.
- Не использовать runtime `fetch` для основной разметки.
- Не начинать визуальный слой без отдельного согласования.
- Выполнять только явно запрошенный подэтап дорожной карты.
- До этапа финальной визуальной полировки не переносить текстовые расхождения из Figma поверх контента текущих partial-компонентов.
- После изменений запускать сборку и обновлять дорожную карту.
- Итоговые отчёты, пояснения, замечания, PR description и комментарии к работе писать на русском языке; технические идентификаторы оставлять на английском. Английский commit message допустим, если он прямо указан в задании.

## Риск-ориентированная политика проверок

- Для CSS-only изменений запускать `npm run verify` и responsive E2E (`npm run test:e2e:responsive`).
- При изменении отдельного компонента запускать только его spec.
- Полный `npm run test:e2e` запускать при изменении общей интерактивной архитектуры, существенном изменении DOM, завершении крупной функциональной контрольной точки или перед публикацией стенда.
- Не переустанавливать Chromium, если существующий запуск Playwright работает.
- Не повторять `npm run build` после успешного `npm run verify`: `verify` уже создаёт production-сборку.
- `node --check` запускать только для изменённых JS/MJS-файлов.
- SHA-256 reference-материалов обязательно проверять при изменении `reference` или перед финальной публикацией, но не после каждого CSS-подэтапа.
